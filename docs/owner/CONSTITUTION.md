# BrowserPilot 项目运行宪章

## 使命

让普通 Chrome 用户只安装插件和运行时模板，就能让 AI 在共享登录态下可靠、可接管、可审计地操作网页；最终用户不需要源码、npm 或重新编译。

## 优先级

1. 用户浏览器与账号安全。
2. 真实页面证据和可复现质量。
3. 核心框架稳定、模板动态扩展。
4. 开发效率与低成本 Agent 并行。

## Owner 保留决策

- 是否修改插件核心或新增公共 primitive。
- 是否接受风险、降低质量门槛或改变架构边界。
- 是否提交、推送、发布或执行其他外部不可逆动作。
- 多个 Agent 结果冲突时的裁决。

## 完成定义

- 进程退出码为 0 只代表 Agent 进程结束，不代表业务通过。
- 站点模板只有最终真实 `install_template + run_template` 返回预期结构时才是 `passed`。
- `blocked` 表示 Host、登录、验证码、限流、站点策略或资源所有权阻断；它不是失败修复完成，也不是通过。
- 没有自检证据的“完成”报告无效。不得为了通过而删除断言、降低最小结果数或把阻断页当正常结果。

## 禁止

- 未经用户明确要求提交、推送或发布。
- 在仓库、日志或文档中写入 PAT、capability token、cookie 等秘密。
- 绕过 lease、伪造 token、抢占其他 Agent 或用户拥有的 Task Space。
- Adapter 修改 `src/`、`native-host/`、生成目录或其他 Adapter 目录。
- 自动化绕过验证码、指纹检测或平台反滥用机制。
- 用“静态文件存在”代替真实浏览器验证。

## 不鼓励

- 为每个站点永久创建一个核心代码维护者。
- 同一 Chrome profile 并行跑多个可见页面任务。
- 在模板里重复实现全局拟人化、锁或调度策略。
- 把历史流水账不断追加进启动文档；历史交给 Git 和 Agent 日志。

## 自愈与停止条件

已领取任务遇到可修复的本地问题时，应在拥有的层内修复、运行最窄红绿测试并继续同一任务。只有缺失凭据、用户接管、不可逆外部动作、持续第三方阻断或需要用户主观产品判断时才停止询问。
